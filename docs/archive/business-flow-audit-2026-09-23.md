# Demo 业务流程走查（2026-09-23，历史归档）

> 本文保存当时的故障、修复与验收记录，不是当前功能规范。其中可恢复删除、历史数据兼容、按完成任务统计作品等行为已被 2026-09-24 重构替换。旧任务 ID、文件名、行号和测试数量仅对应各段记录时点。当前规则以 [重构基线](../refactor-baseline.md)、[媒体生命周期](../media-lifecycle-design.md) 和 [模板结构](../motion-template.md) 为准。

本轮以浏览器实际操作为主，以本机 API 响应和源码核实原因。未修改业务代码。只检查业务流程，不评价视频模型效果。以下结果不能替代并发、异常恢复或真实供应商接入测试。

## 实际走过的路径

管理员登录 → 上传参考视频与预览视频 → 发布双人物模板 → Explore 查看 → 退出登录 → 点击使用模板 → 普通用户登录 → 上传两张图片 → 选择 1080p / 8 秒 → 提交 → Collection 查看任务 → 刷新后查看完成状态 → 播放/下载 → 核对积分 → 后台查看任务。

补充路径：单人物模板先上传有效图片，再替换为无效图片后提交；发布表单填写后切换后台标签再返回。

## 已复现故障

### P0：任务已完成并结算积分，作品却无法交付

- 双人物任务成功完成，48 积分已结算，但作品播放报错。
- 已登录请求 `/api/creations/737628c3-8c31-46ff-b237-17add7f20db1/video`，返回 404 JSON，而非视频。
- 新模板 `/api/templates/0e596a90-78a1-4c1e-bc61-ba378b8c9fdc/preview-video` 同样返回 404。后台、广场和生成弹窗中的预览均受影响。
- 同一份有效 sample.mp4 作为内置模板预览返回 206 / video/mp4，上传后文件大小和 SHA256 与原文件一致。
- 原因：默认数据目录是 `.data`；多个媒体路由将包含隐藏目录段的绝对路径直接传给 `res.sendFile`，底层 send 默认忽略 dotfiles，因而返回 404。参考视频与结果路由也使用相同模式。
- 位置：`server/app.mjs:36,266,404,413,506,565`；`node_modules/send/index.js:458`。
- 既有 API 测试使用不含隐藏路径段的临时目录，未覆盖实际部署路径。
- 修复验收：使用真实 `.data` 路径，验证参考视频、模板预览、作品播放和下载，包含 Range 请求与访问权限。不能仅以任务 completed 作为交付成功的依据。

### P1：换图失败仍能使用旧图片提交并扣费

- 单人物模板上传有效 JPG，随后选择内容无效的 JPG 文件替换。
- 页面提示“请上传有效的 JPG、PNG 或 WebP 图片，尺寸不超过 2500 万像素。”，但旧缩略图仍在，生成按钮仍启用。
- 点击生成成功创建任务并结算 12 积分。任务前缀 `fe39f173`，补充描述“走查：图片替换失败后的提交”。
- 原因：`src/CustomCreateModal.tsx:29–39` 上传失败只设置错误，没有明确处理该槽位旧素材的使用状态；提交读取旧 uploads。
- 修复验收：换图失败后明确阻止提交，或者要求用户明确恢复使用旧图；不能让错误状态下的提交静默沿用旧素材。

### P2：发布草稿在切换后台标签后丢失

- 模板名称填写“未发布草稿走查”、动作说明填写“检查切换标签后是否保留”。
- 点击“任务列表”，再回“模板目录”，名称和说明均清空，离开时没有提示。
- 原因：`src/AdminCatalogPage.tsx` 将表单保存在组件本地状态；`src/App.tsx:1485` 条件渲染导致切换标签时卸载。
- 修复验收：保留未提交配置与已上传素材引用，或在离开时明确提醒；上传文件本身的恢复要区别于可序列化表单字段。

### P2：登录后没有继续此前选择的模板

- 未登录时点击新模板“使用”，按引导登录普通账户后只回到广场，没有打开该模板的生成窗口。
- 原因：`src/App.tsx:760–800` 没有保存和恢复待执行的模板选择。
- 修复验收：登录成功继续原操作；登录取消时正常返回浏览。

### P2：Collection 的作品统计与已完成卡片不一致

- 实际看到“2 件作品 · 0 个任务处理中”，同时存在 3 张已完成任务卡片，“全部”也显示 3。
- 原因：标题使用 creations.length，卡片使用 jobs；历史任务和新作品记录的覆盖范围不同。
- 位置：`src/App.tsx:1205` 及后续 visibleJobs 渲染。
- 修复验收：明确作品与任务的展示口径，兼容历史完成记录，统计与列表一致。

## 业务功能缺口

### P1：模板发布后缺乏纠错和下架入口

后台已发布列表只有展示，没有编辑、替换预览、下架入口。发布错误后无法通过正常业务界面修正，已损坏的预览仍会出现在 Explore。

建议至少支持下架及元信息修正；生成配置发生改变时发布新版本，历史任务继续引用原版本。位置：`src/AdminCatalogPage.tsx:179`。

### P1：双人物槽位没有可理解的角色对应关系

发布页只能选择单人物/双人物，不能说明参考视频中哪个角色对应哪个输入。使用者看到的“人物 A 图片 · 对应人物 A”只是重复标签。

这属于输入定义不完整，与模型效果无关。建议允许管理员配置角色名称、动作/位置说明及示意图，使用时展示相同说明。位置：`src/AdminCatalogPage.tsx:82–85`、`src/CustomCreateModal.tsx:64`。

## 修复与复验（9 月 23 日至 24 日）

上述七项已处理：

- 媒体路由用受限媒体目录作为 sendFile root，读取数据库中确定的文件名；不全局放开隐藏文件访问。原先 404 的存量预览和作品恢复可访问。
- 选择新图片立即清除旧素材，上传失败时禁用提交；关闭按钮在请求期间禁用。
- 管理后台新增模板管理：修改名称、说明、分类、角色说明、替换示例成片、下架、重新上架。角色说明变更创建新版本，历史任务保留原快照；使用更新时间校验，拒绝覆盖其他编辑。
- 发布页可填写单/双人物角色说明，生成窗口展示同一说明。
- 发布表单在页面和后台标签切换时保留；按用户将可序列化草稿保存在当前标签会话中。刷新前尚未上传的文件需要重新选择，页面会提醒。部分参考文件上传成功时，不会在恢复后把部分列表误认为完整输入。
- 登录保存待使用的模板 ID，登录成功刷新目录后继续打开；取消登录清除待执行操作。
- Collection 统计与卡片使用相同任务集合，已完成历史任务也计入作品数。
