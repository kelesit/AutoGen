# Playbox Studio — 全栈能力演示

参考 Playbox 的模板探索、创作任务、作品库和积分结构制作的独立 demo，与原网站无关联。采用非露骨的摄影素材，不复用原站内容或代码。

**定位：向合作方展示可运行的全栈业务流程。AI 输出使用固定演示样片，不是真实生成结果。**

## 运行

需要 Node.js 24+。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。前端使用 Vite+，通过代理访问 8787 端口的后端。

构建后也可运行完整后端演示：

```sh
npm run build
npm start
```

此时打开 http://127.0.0.1:8787 。默认仅监听本机，不向外网公开。

## 已完成的功能

- React + Vite+ 模板广场、登录、上传、收藏、作品库和管理员后台。
- 管理员可在“模板目录”上传 1–3 段动作参考视频、示例成片并配置图片槽位和生成规格，发布后立即进入 Explore；普通用户按槽位上传人物图、获取报价、提交任务，再在 Collection 查看作品。任务保留模板版本、素材和价格快照。动作参考与广场预览独立存储。
- 模板管理提供新增、搜索/筛选/分页、详情、完整编辑和不可恢复删除。参考视频、Prompt、图片槽位和生成规格变更创建新版本，历史任务保留原快照；修改与删除检查并发版本。删除保留历史身份与任务快照，不提供恢复。
- 发布草稿在切换页面时保留，并按账户保存于当前标签会话；刷新后恢复表单与完整的已上传素材引用。尚未上传的本地文件需重新选择，页面会提示。
- 用户登录后继续打开原先选择的模板；换图失败清除旧素材并阻止提交。
- 独立 Worker、SQLite 持久任务表、租约与恢复、全局并发门控。
- 模板目录、任务提交、积分和作品查询按业务模块拆分；保存完成后才建立独立作品记录。
- 提交结果未知时查原任务；无法可靠查单时进入人工核查，不盲目重新生成。
- 积分冻结 / 结算 / 释放；供应商模拟成本单独记账；模板和价格快照。
- 生成与保存分阶段，私有文件落盘和校验后结算，保存失败不重新生成。
- 任务时间线、外部调用记录、Worker 心跳、管理员阶段恢复和重复/乱序事件演示。
- 浏览器提交前保存请求键，刷新后找回未确认任务；有明确标注的响应丢失演示开关。
- 统一媒体资产、结构化引用、素材库删除、作品删除与后台文件清理；进行中任务及共享引用保护。
- 新开发基线不读取旧数据库，不再提供训练/审核、静态模板、旧任务播放等兼容链路。

## 运行结构

`npm run dev` 启动前端、API、Worker 三个进程。`npm start` 启动 API（服务构建后的页面）与 Worker 两个进程。也可单独运行 `npm run worker`，在同一数据目录下启动额外 Worker。

默认数据在 `.data-v2/`：`playbox.sqlite` 是业务数据库，`provider.sqlite` 是模拟供应商数据库，`assets/` 是唯一私有业务媒体目录。重启不会清空。旧 `.data/` 保留但不读取；不提供迁移。`DATA_DIR` 可指定新的开发目录，指定不兼容旧库会明确报错。`PORT`、`HOST`、`APP_ORIGIN`、`COOKIE_SECURE` 控制 API 环境。开发代理固定指向 8787，开发时若修改 API 端口还需同步修改 `vite.config.ts`；API 与 Worker 必须使用相同的 `DATA_DIR`。

## 模拟边界

生成适配器会持久保存外部接单记录，并注入超时、限流、生成失败和下载失败；输出仍是固定 CC0 花卉视频。不会根据输入图片/提示词生成视频，实际视频规格也不随参数变化。模拟调用不经过公网，不能代替真实供应商协议和网络联调。

演示积分没有货币价值；供应商成本使用 `mock_units`。当前只做管理员模板目录，生成仍是固定样片；不包括真实模型效果、训练、支付、订阅和创作者分成。作品与模板删除不提供恢复，任务和积分记录保留。文件只在无有效引用时清理，删除失败后台重试。参考与预览保留在素材库，可显式删除；临时图片上传 24 小时后进入清理候选，仍被未结束任务占用的图片继续保留；到期不代表立即失效。视频目前只做基本格式/体积校验，真实解码校验、视频转码、对象存储和生产容量验证尚未实现。
